# ddakrate 공모전 제출서 초안

> 상태: **이전 배경 자료.** 현재 제출 내용은 [기획서](2026_FINANCIAL_AI_CHALLENGE_PLAN_DRAFT.md)와 [기능 명세서](2026_FINANCIAL_AI_CHALLENGE_FUNCTION_SPEC_DRAFT.md)를 우선한다.  
> 데이터 기준(아래 표): 2026-09-05 normalized publication으로 갱신  
> 별도 입력 필요: 공모전명, 팀명, 팀원, 제출 분량, 데모 URL, GitHub 공개 범위

## 1. 서비스명

**ddakrate(딱금리) — 대화로 실제 받을 수 있는 금융상품을 찾는 AI 추천 서비스**

## 2. 한 줄 소개

사용자가 원하는 기간과 금액, 실제로 충족할 수 있는 우대조건을 대화로 확인하여 예금·적금·파킹통장·CMA를 비교하고, 공식 근거에 기반한 예상 금리와 세전 이자를 계산하는 금융상품 탐색 서비스입니다.

## 3. 해결하려는 문제

금융상품 비교 화면에는 보통 광고 최고금리가 먼저 보입니다. 하지만 실제 금리는 급여이체, 카드 사용, 첫 거래, 납입 횟수, 특정 서비스 이용 등 여러 조건에 따라 달라집니다. 상품마다 가입 기간과 납입 방식도 다르므로, 금리 숫자만 정렬해서는 사용자가 실제로 받을 수 있는 혜택을 비교하기 어렵습니다.

기존 검색 방식에는 다음과 같은 한계가 있습니다.

- 광고 최고금리와 사용자가 실제 받을 수 있는 금리가 구분되지 않습니다.
- 같은 금리라도 납입 방식과 기간이 달라 실제 이자금액이 달라집니다.
- 복잡한 우대조건을 사용자가 상품설명서마다 직접 읽고 판단해야 합니다.
- 예금·적금·파킹통장·CMA의 수익 구조가 다른데도 하나의 확정금리처럼 비교되기 쉽습니다.
- 확인되지 않은 정보가 누락되거나 임의의 기본값으로 처리되면 추천 결과를 신뢰하기 어렵습니다.

ddakrate는 사용자가 상품 조건표를 해석하는 대신, 자연어로 자신의 상황과 의향을 답하면 해당 조건을 구조화하고 금융 계산 엔진이 다시 평가하도록 설계했습니다.

## 4. 핵심 해결 방식

### 4.1 대화로 조건을 확인하는 상품 탐색

서비스는 먼저 상품군, 희망 기간, 납입·예치 금액, 가입 대상과 공통 우대 의향을 확인합니다. 이후 현재 금리가 높은 후보부터 상품별 미확인 조건을 하나씩 질문합니다. 사용자는 정해진 명령어나 금융 용어를 알 필요 없이 자연어로 답하거나 조건의 의미를 다시 물어볼 수 있습니다.

답변이 들어올 때마다 현재 사용자 상태와 상품 조건을 다시 대조하고 후보와 순위를 갱신합니다. 사용자가 이전 답변이나 희망 조건을 바꾸면 전체 탐색을 처음부터 반복하지 않고 변경된 상태를 반영해 재계산합니다.

### 4.2 LLM과 금융 계산 엔진의 역할 분리

LLM은 자연어 인터페이스 역할을 담당합니다.

- 사용자 발화에서 변경된 조건 해석
- 질문의 의도와 공식 조건 설명
- 구조화된 추천 결과를 이해하기 쉬운 문장으로 전달

가입 가능 여부, 조건 충족 상태, 금리 적용, 현금흐름, 예상 이자와 상품 순위는 결정론적 엔진이 계산합니다. LLM이 금리나 상품 조건을 만들어내거나 순위를 임의로 결정하지 않습니다.

```text
사용자 자연어
→ LLM이 답변의 의미를 구조화
→ 현재 사용자 상태에 차이만 반영
→ 공식 상품 조건과 재평가
→ 적용 가능 금리·현금흐름·세전 이자 계산
→ 다음 질문 또는 추천 결과 제시
```

### 4.3 서로 다른 네 상품군을 같은 화면에서 안전하게 비교

ddakrate는 적금, 예금, 파킹통장, CMA를 하나의 탐색 흐름에서 다루되 수익 구조를 억지로 동일하게 만들지 않습니다.

- 적금: 월 납입액과 회차별 예치 기간을 반영합니다.
- 예금: 목돈의 일시 예치와 계약기간을 반영합니다.
- 파킹통장: 잔액 구간별 금리와 한계구간 적용 방식을 보존합니다.
- CMA: RP형 공시수익률과 MMF·MMW 등 실적배당을 구분합니다.

실적배당 상품은 확정 수익처럼 표시하지 않으며, 계산에 필요한 공식 값이 부족한 상품은 0%로 처리하지 않습니다.

## 5. 데이터 신뢰성 설계

금융기관, 상품, 공통 조건, 금리 항목과 근거 문서를 서로 연결된 데이터로 관리합니다. 후보 발견에는 비교 서비스 목록을 쓰고, 공식 재확인 근거와 미확인 Data Gap을 구분합니다.

현재 normalized publication(2026-09-05)에는 다음 데이터가 포함되어 있습니다.

| 항목 | 현재 수치 |
|---|---:|
| 전체 상품 | 4,295개 |
| 현재 판매 중 | 4,289개 |
| 판매 종료 보존 | 3개 |
| 판매중지 / 상태 미확인 | 2개 / 1개 |
| 적금 | 2,185개 |
| 예금 | 1,824개 |
| 파킹통장 | 218개 |
| CMA | 68개 |
| 상품 연결 금융기관 | 721개 |
| 기관 master | 1,704개 |
| SourceDocument | 9,183개 |
| EvidenceRef | 15,430개 |

비교 서비스 발견본과 공식 재확인 근거를 구분한다. 위 근거 수가 전 항목의 공식 검증 완료를 뜻하지는 않는다. 2026-08-25 소규모 발행(209개)의 누적 validation PASS 429건은 그 시점 수치이며 현재 카탈로그 전수 검수로 읽지 않는다.

상품 파일과 발행 manifest는 SHA-256으로 검증합니다. 상품 조건이 변경되면 과거 값을 덮어쓰지 않고 새 버전을 발행합니다. 공식 자료에서 확인하지 못한 값은 임의로 채우지 않고 `Data Gap`으로 남겨 화면과 API에서 확인할 수 있게 합니다.

공식 금리·산식이 부족하거나 실적배당인 상품은 확정 수익처럼 가장하지 않습니다. 계산 가능 상품 수는 발행 시점에 따라 달라지므로 고정 홍보 숫자로 쓰지 않습니다.

## 6. 주요 사용자 경험

1. 사용자가 “1년 동안 매달 30만 원씩 넣을 적금을 찾고 있어”처럼 자연어로 시작합니다.
2. AI가 답변에서 상품군, 기간, 금액을 구조화합니다.
3. 서비스가 가입 대상과 금리에 영향이 큰 공통 의향을 순서대로 확인합니다.
4. 판매 중 상품을 필터링하고 현재 조건에서 유리한 후보를 계산합니다.
5. 상위 후보의 미확인 우대조건을 금리 영향 순서로 질문합니다.
6. 사용자의 답변이 들어올 때마다 실제 적용 가능 금리와 세전 예상 이자를 재계산합니다.
7. 결과 카드와 상세 화면에서 추천 이유, 기간, 납입 계획, 금리 기준일, 우대조건, Data Gap과 공식 출처를 확인합니다.

사용자는 질문 중에도 조건의 의미를 다시 물어볼 수 있습니다. 이때 LLM이 공식 근거 범위 안에서 설명하고, 아직 답하지 않은 기존 질문은 그대로 유지합니다.

## 7. 차별점

### 광고 최고금리가 아닌 실현 가능한 결과

단순 최고금리 순위가 아니라 사용자의 납입 계획과 실제 충족 가능한 조건을 반영합니다. 사용자가 “모르겠다”고 답한 조건은 답변 완료로 기록하되 해당 우대를 보수적으로 제외합니다.

### 생성형 AI와 결정론적 금융 계산의 결합

자연어 이해와 설명에는 LLM을 사용하지만, 가입 판정과 숫자 계산은 검증 가능한 코드가 담당합니다. 생성형 AI의 편의성을 취하면서 금융정보의 환각 위험을 줄였습니다.

### 불확실성을 숨기지 않는 추천

공식 자료가 없는 값을 0, false 또는 “조건 없음”으로 바꾸지 않습니다. `UNKNOWN`, `UNSUPPORTED`, `Data Gap`을 구분하여 추천 결과의 계산 가능 범위를 사용자에게 공개합니다.

### 공식 근거까지 추적 가능한 데이터

상품의 금리와 우대조건에서 공식 원문까지 연결할 수 있습니다. 기관 고유 서비스나 걸음 수처럼 특수한 조건도 별도 문구로 흩어놓지 않고 공식 상품 조건으로 구조화합니다.

### 개발자용 투명성 화면

별도의 runtime inspector에서 각 대화 turn의 사용자 입력, LLM 해석, 질문 생성, 상태 변경과 Engine 입출력을 구분해 볼 수 있습니다. 이를 통해 잘못된 추천이 자연어 해석, 데이터, 질문 설계 또는 계산 중 어디에서 발생했는지 추적할 수 있습니다.

## 8. 구현 및 검증

- FastAPI 기반 Web runtime과 동일 origin UI
- OpenAI Responses API 및 strict Structured Outputs 사용
- normalized index와 manifest를 기준으로 한 상품 로딩
- 상품 파일·manifest SHA-256 무결성 검증
- 기관·상품·조건·금리 참조 무결성 검증
- 판매 종료 상품은 데이터에 보존하되 기본 추천 후보에서 제외
- MOCK 모드와 실제 OpenAI 모드를 분리하여 회귀 테스트 가능
- 자연어 대화 이력과 내부 audit 기록을 분리 보존
- 사용자 응답 경로의 저장을 비동기화해 체감 지연 최소화

현재 데이터 publication은 상품 4,295개와 근거 기록 15,430개를 포함합니다. 데이터가 부족하거나 계산을 지원하지 않는 상품도 전체 서버를 중단시키지 않고 명시적인 미확인 상태로 유지합니다. 우대 원문 의미 분석은 실험 기능이며 기본값은 꺼져 있습니다.

## 9. 기대 효과

사용자는 여러 금융기관의 상품설명서를 직접 비교하는 시간을 줄이고, 자신의 상황에서 받을 가능성이 높은 금리와 예상 이자를 확인할 수 있습니다. 금융상품에 익숙하지 않은 사용자도 대화를 통해 조건의 의미를 이해하면서 선택할 수 있습니다.

금융기관이나 비교 서비스 관점에서는 추천 결과의 근거와 계산 과정을 추적할 수 있어, 단순 생성형 답변보다 검증과 유지보수가 쉽습니다. 동일한 구조는 향후 금융기관 API 및 마이데이터와 연결해 사용자가 직접 답해야 하는 조건을 자동 확인하는 기반으로 확장할 수 있습니다.

## 10. 향후 계획

- 비교 서비스로 넓힌 후보의 공식 자료 재검증 확대
- 실시간 이벤트, 쿠폰 발급 조건과 앱 확인 경로 데이터 보강
- 금융기관 API·마이데이터 연결을 통한 조건 자동 확인
- 실적배당 CMA를 위한 별도 성과 비교 지표 설계
- 실제 사용자 대화 이력을 바탕으로 질문 데이터와 조건 설명 정밀화
- 배포 환경, 접근 제어와 운영 모니터링 구축

## 11. 시연 시나리오

### 시나리오 A: 월 적금 찾기

```text
사용자: 1년 동안 매달 30만 원씩 넣을 적금을 찾고 있어.
서비스: 발화에서 적금·12개월·월 30만 원을 구조화합니다.
서비스: 가입 대상과 공통 우대 의향을 확인합니다.
사용자: 급여계좌 변경은 가능하지만 카드는 새로 만들고 싶지 않아.
서비스: 행동별 의향을 나누어 저장하고 후보를 재계산합니다.
서비스: 상위 상품의 미확인 조건을 질문합니다.
사용자: 그 조건이 정확히 무슨 뜻이야?
서비스: 공식 근거 안에서 설명한 뒤 기존 질문을 유지합니다.
사용자: 그 조건은 충족할 수 있어.
서비스: 적용 가능 금리와 세전 예상 이자를 다시 계산해 결과를 보여줍니다.
```

