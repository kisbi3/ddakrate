## 1. MVP 구현 범위*

딱금리는 로그인 없이 웹에서 바로 쓰는 대화형 금융상품 탐색 MVP다. 화면은 왼쪽 채팅과 오른쪽 추천 목록으로 나뉘며, 사용자가 조건을 말하거나 고칠 때마다 두 영역이 같은 상태로 함께 갱신된다. 예금·적금·파킹통장·CMA를 한 흐름에서 비교하고, 광고 최고금리가 아니라 현재 답변으로 계산한 예상 금리와 예상 이자를 보여 준다.

질문은 두 단계다. 먼저 상품군, 납입·예치 계획, 가입 명의, 생년월일, 청년·장병 정책 상품, 기관 범위, 급여·카드·첫거래 의향, 최근 예적금·청약 보유 기관을 확인한다. 그다음 현재 상위 후보의 미확인 우대·가입 조건만 이어서 묻는다. 답은 선택형 버튼과 자연어를 모두 받으며, 조건의 뜻을 다시 물으면 설명만 하고 기존 질문을 유지한다.

기본 후보는 2026-09-05 발행본의 판매 중 4,289개다. 전체 발행 상품은 4,295개이며 판매 종료·중지 상품은 데이터에 남기되 기본 목록에서 뺀다. 오른쪽에서는 상품군, 1금융권, 비대면, 개별 기관, 상품명으로 목록을 좁힐 수 있고, 카드를 누르면 우대조건·출처·Data Gap을 본다. 같은 세션의 계산 과정은 `/debug`에서 확인할 수 있다.

포함하지 않는 범위는 다음과 같다. 실제 상품 가입, 계좌·마이데이터 조회, 회원가입, 우대 원문을 AI가 실행 규칙으로 컴파일하는 의미 분석(코드는 있으나 기본 OFF)은 MVP 검증 경로에 넣지 않는다.

## 3. 사용자 이용 흐름*

1. 배포 URL에 접속한다. 회원가입이나 테스트 계정은 필요 없다. 왼쪽 채팅에 `1년 동안 매달 30만 원씩 저축할 상품을 찾고 있어`처럼 입력한다.
2. 위쪽 `AI는 잘 이해했나?`에 적금, 12개월, 월 30만 원이 뜨는지 확인한다. 틀리면 그 자리에서 고친다. 오른쪽에는 현재 조건의 추천이 바로 나타난다.
3. 이어지는 사전 질문에 답한다. 개인 명의인지, 생년월일, 청년·장병 정책 상품, 은행만 볼지, 급여이체·카드·새 거래 의향, 최근 6개월 예적금·청약 보유 기관이 대표 항목이다. 한 번에 여러 답을 말해도 된다.
4. 사전 질문이 끝나면 상위 후보의 미확인 조건을 묻는다. 화면 예처럼 가입 후 마케팅 동의, 자동이체 유지, 국민은행 주택담보·전세자금 대출 이용, 모바일·인터넷 가입 가능 여부를 선택형 버튼으로 답하거나 자연어로 답한다. 뜻을 모르면 다시 묻고, 설명 후에도 질문은 남는다.
5. 답변마다 오른쪽 상위 3개와 목록의 기간·예상 이자·예상 금리·최고 금리가 바뀐다. `#적금` `#1금융권` `#비대면만` 또는 은행 선택으로 목록만 좁힐 수 있다.
6. 1위 카드를 눌러 우대조건과 공식 출처, 확인하지 못한 항목을 본다. 대화로 이전 답을 바꾸면 같은 화면에서 순위가 다시 맞춰진다.
7. 필요하면 같은 주소의 `/debug`에서 이번 대화의 해석과 계산 과정을 확인한다.

## 4. AI 및 데이터 처리 방식*

입력은 사용자의 자연어 한 줄 또는 선택형 버튼이다. 출력은 왼쪽의 다음 질문·설명과 오른쪽의 추천 목록·상세다. 처리 순서는 아래와 같다.

```text
사용자 발화 또는 선택형 답변
→ LLM이 이번 턴에서 바뀐 조건만 strict Structured Output으로 추출
→ 애플리케이션이 현재 상태에 차이만 검증·병합
→ Engine이 판매 중 후보의 가입 조건, 금리, 현금흐름, 세전 이자, 순위를 계산
→ 왼쪽 다음 질문과 오른쪽 추천을 한 번에 갱신
```

생성형 AI는 OpenAI Responses API의 `gpt-5.6-luna`를 기본 모델로 쓴다. LLM은 의도 해석, 조건 설명, 결과 문장만 담당한다. 가입 가능 여부, 우대 충족 여부, 적용 금리, 예상 이자, 순위는 결정론적 Engine이 계산하므로 같은 입력과 같은 상품 버전이면 숫자가 같다.

데이터는 2026-09-05 발행 기준 721개 기관의 상품 4,295개다. 판매 중 4,289개를 기본 후보로 쓰고, SourceDocument 9,183개와 EvidenceRef 15,430개를 연결한다. 후보 발견에는 비교 서비스 목록을 참고했고, 공식 페이지·상품설명서로 재확인한 값과 아직 확인하지 못한 Data Gap을 구분한다. 확인되지 않은 금리나 조건을 LLM이 채워 넣지 않는다.

이름, 주민등록번호, 계좌번호, 비밀번호는 받지 않는다. 별도의 회원 계정이나 마이데이터 연결도 없다. 대화에 적은 자금 계획과 조건 의향은 세션 진행과 `/debug` 기록을 위해 서버에 남을 수 있으므로, 실제 개인식별정보는 입력하지 않는 것을 원칙으로 한다.

## 5. MVP 검증 방법*

- 배포 URL: `[배포 URL 입력]`
- 권장 환경: 데스크톱 최신 Chrome
- 별도 계정: 필요 없음. 접속 후 채팅만 하면 된다.

### 검증 시나리오

1. `1년 동안 매달 30만 원씩 저축할 상품을 찾고 있어` 입력  
   예상: `AI는 잘 이해했나?`에 적금·12개월·월 30만 원이 뜨고, 오른쪽에 적금 추천이 나타난다.
2. 사전 질문과 상위 후보 조건에 `네`, `아니요`, `아직 계획이 없어요` 또는 짧은 자연어로 답변  
   예상: 왼쪽 질문이 다음으로 넘어가고, 오른쪽 예상 이자·예상 금리·순위가 다시 계산된다.
3. `그 조건이 무슨 뜻이야?` 입력  
   예상: 조건을 설명하고, 아직 답하지 않은 기존 질문은 그대로 남는다.
4. `#1금융권` 또는 `#비대면만`을 누름  
   예상: 보이는 목록만 걸러지고, 대화에서 확인한 기간·금액 조건은 유지된다.
5. 1위 상품 카드를 누름  
   예상: 우대조건, 금리 기준일, 출처, 미확인 항목을 볼 수 있다.
6. 주소 뒤에 `/debug`를 붙임  
   예상: 같은 세션의 대화, LLM 해석, 상태 변경, Engine 호출이 나뉜다. 계정은 묻지 않는다.

### MVP 제한사항

- 실제 상품 가입과 금융기관 계좌·마이데이터 조회는 지원하지 않는다.
- 실시간 이벤트, 쿠폰, 앱 메뉴 경로는 보유 데이터에 있는 범위만 안내한다.
- 실적배당 CMA는 확정 수익을 계산하거나 보장하지 않는다.
- 공식 금리·산식이 부족한 상품은 숫자를 만들지 않고 Data Gap을 표시한다.
- 화면의 예상 이자는 세전 단순 예시이며 은행의 일수·절사·세금 적용과 다를 수 있다.
- 답변 속도는 외부 모델 API와 네트워크 상태에 따라 달라질 수 있다.
- 우대 원문 의미 분석은 실험 기능이며 기본값은 꺼져 있다. 기본 검증 경로에 넣지 않는다.
- 발행 카탈로그의 모든 근거가 공식 재확인을 통과했다는 뜻이 아니다.
- `/debug`는 이 배포본에서 주소만 알면 열린다. 심사·개발 확인용이며 주민번호·계좌는 기록하지 않는다.
