## 작업 1. 지금 이미 물어보는 것

출처는 코드다. 질문은 발명하지 않았다.

- 사전 질문 순서·적용 조건: `src/eligibility/search/pre_search.py` (`QUESTION_ORDER`, `_is_applicable`, `_question_text`)
- 의향 거절이 후보 질문에 미치는 영향: `src/eligibility/pre_search_handler.py`, `src/eligibility/search/questions.py`
- 상품 조건 묶기·문구 가족: `RankingAwareQuestionPlanner.question_family_id`, `src/eligibility/question_policy.py`

### 1.1 사전 질문

의미 분석은 사전 질문이 남아 있으면 우대 글을 읽지 않는다 (`DEFERRED`). 아래 열의 “다시 묻지 않음”은 그 전제 위에 있다.

| 질문 ID | 의미 | 의미 분석이 다시 물으면 안 되는지 |
|---|---|---|
| `PRODUCT_TYPE` | 적금 / 예금 / 파킹·CMA | **다시 묻지 않음.** 검색 범위 자체다. |
| `CONTRIBUTION_AND_TERM` | 납입 금액·주기와 기간(또는 파킹의 비교 기간) | **다시 묻지 않음.** 이자 계산 입력이다. |
| `APPLICATION_CAPACITY` | 개인 / 개인사업자 / 법인 명의 | **다시 묻지 않음.** 가입대상 공통 fact다. |
| `BIRTH_DATE` | 가입자 생년월일 | **다시 묻지 않음.** 만 나이·청년 상품에 공통 적용. 자녀 생년월일과 섞지 않음. |
| `YOUTH_POLICY_ACCOUNT_HOLDING` | 청년미래적금·청년도약계좌 중복 | **다시 묻지 않음.** 적금 검색에서 전역 fact. 원문이 “청년 정책 중복”이어도 새 칸 금지. |
| `SOLDIER_TOMORROW_SAVINGS_ELIGIBILITY` | 장병내일준비적금 복무 대상 | **다시 묻지 않음.** 후보에 해당 상품이 있을 때만 나오며 전역 fact. |
| `PROTECTION_AND_CMA_SCOPE` | 예금자보호 파킹만 / CMA 포함 | **다시 묻지 않음.** 파킹+CMA가 같이 남을 때만. |
| `INSTITUTION_SCOPE` | 은행 / 저축은행 / 증권 범위 | **다시 묻지 않음.** 의미 분석을 1금융권 전용으로 하드코딩하지도 않음. 사용자가 은행만 골랐으면 그때 후보가 은행이다. |
| `COMMON_BENEFIT_WILLINGNESS` | 새 거래·급여계좌·카드 추가 조건 의향 | **새 칸 만들지 않음.** 원문이 카드 발급·사용, 급여이체·급여계좌, “새 은행 거래” 의향이면 여기로 연결. 명시적 `UNWILLING`/`NOT_APPLICABLE`은 해당 우대 질문을 억제한다. 의향이 있다고 우대 달성을 확정하지 않음. |
| `INSTITUTION_PRODUCT_HOLDING_HISTORY` | 최근 6개월 예적금·청약 보유 기관 | **새 칸 만들지 않음.** “그 은행에 최근 거래가 없다”는 첫거래 판단용이다. “아무 은행이나 계좌를 내도 된다”와 섞지 않음. 상품별 원문이 첫거래·신규고객·당행 미보유면 이 답으로 해당 없음을 판단하고, 기관별 이력이 부족하면 메모만 남김. |

`COMMON_BENEFIT_WILLINGNESS`가 실제로 받는 하위 값:

| 하위 키 | 의향 대상 | 다시 물으면 안 되는 원문 예 |
|---|---|---|
| `first_transaction_willingness` | 새 금융기관 거래 | 신규고객, 첫거래, 직전 N개월 당행 예적금 미보유 |
| `salary_transfer_willingness` | 급여계좌 변경·급여이체 | 급여이체, 급여실적, 급여수령 계좌 |
| `card_willingness` | 카드 발급·사용 | 카드 발급, 카드 이용실적, 결제계좌 지정 |

마케팅 동의·앱 로그인·오픈뱅킹·쿠폰은 이 통합 사전 질문에 **의도적으로 없다**. 상품 조건 단계에서 기존 플래너 가족으로 묻는다. 의미 분석이 “마케팅 하실래요?”를 새로 만들면 안 된다.

### 1.2 상품 조건 질문 (플래너가 이미 묶는 것)

`RankingAwareQuestionPlanner`는 Top 3와 3위권 도전 가능 후보만 묻고, 같은 사용자 변수는 한 질문으로 묶는다. 카드 거절·급여 거절·첫거래 거절이 있으면 해당 금리 우대 질문은 내지 않는다.

| 질문 가족 / 식별 | 의미 | 의미 분석이 다시 물으면 안 되는지 |
|---|---|---|
| `ACTION-CARD_MONTHLY_SPEND_LIMIT` | 월 카드 이용실적 한도 | **다시 묻지 않음.** 숫자 칸은 이미 있다. 원문 카드 실적은 이 가족에 연결. |
| `action_id`가 있는 급여이체·급여월수 | 급여이체 실적 | **다시 묻지 않음.** 기존 typed 급여 질문 유지. |
| `NEW_CARD_ISSUANCE` | 새 카드 발급 의향 | 사전 질문 9번 카드 의향과 중복되지 않게 연결. 이미 거절이면 묻지 않음. |
| `CARD_SETTLEMENT_ACCOUNT` | 카드 결제계좌 지정 | 카드 의향 가족. 새 칸 금지. |
| 첫거래 / `FIRST_DEPOSIT_OR_SAVINGS_CUSTOMER` / `NEW_CUSTOMER` | 그 은행 신규·첫거래 | 사전 질문 10번 보유 이력으로 연결. “아무 데나 계좌 개설” 칸 금지. |
| `MARKETING` / `CONSENT` | 가입 후 상품 안내·마케팅 수신 동의 유지 | **새 칸 금지.** “앞으로 동의할 의향”은 여러 은행에 같이 쓸 수 있다. “경남은행에 이미 동의됨”은 신한으로 옮기지 않음. |
| `AUTO_TRANSFER` / `AUTOMATIC_TRANSFER` | 가입 후 자동이체 납입 유지 | 기존 미래 의향 질문. 새 칸 금지. |
| `APP_LOGIN` / `APP_USAGE` / 오픈뱅킹·MyData | 앱·오픈뱅킹 이용 | 기존 미래 의향. 사전 질문 9번에 억지로 넣지 않음. |
| `MEMBERSHIP` / `REGISTRATION` | 제휴·서비스 회원가입 | 기존 미래 의향. |
| 인터넷/모바일뱅킹 가입 | 비대면 가입 채널 | `question_policy`가 이미 고정 문구로 묶음. |
| 주택담보·전세자금대출 보유/예정 | 해당 은행 주담대·전세자금 | 이미 특별 가족. 새 칸 금지. |
| KB 교차거래 우대 | 급여이체 또는 KB국민카드 30만원 | 이미 한 질문. 카드/급여 칸을 둘로 쪼개지 않음. |
| `PRODUCT_HOLDING` 원문 | 당행 예적금·청약 보유 | 사전 질문 10번이 담당. 상품별 “청약 있나요?”를 다시 만들지 않음. |
| `ELIGIBILITY_TEXT::…::EXISTING_ACCOUNT_STATUS` | 1인 1계좌 원문 재발견 | 이미 typed 한도 규칙이 있으면 묻지 않음. |
| 본인확인 서류 소지 | 주민등록증·운전면허 | 비교 질문이 아님. 가입 단계 안내. |
| 추첨 당첨 결과 | 기관만 아는 이벤트 결과 | 사용자에게 묻지 않음. |
| 수수료 면제·사은품 | 정보성 혜택 | 금리 질문이 아님. |

가입자 **본인** 생년월일은 사전 질문 `BIRTH_DATE`다. 자녀 수·자녀 생일·혼인일·가입자 본인 임신만 의미 분석 칸으로 남긴다.

### 1.3 표에 없는 칸을 만들기 전에

1. 위 표의 기존 질문에 붙일 수 있는지 한 줄로 적는다.
2. 못 붙이면 이번 단계에서는 `UNRESOLVED`(자동 판단 못함)로 둔다.
3. 새 칸 제안이 나와도, 기존 질문으로 부족한 이유가 한 문장이어야 한다.

**이번 조사의 결론:** 1금융권 unread 절을 위해 새 칸은 만들지 않는다. 이유는 작업 2.

## 작업 2. 1금융권 unread 우대 글 분류

범위는 계획과 같다.

- 기관 유형 `BANK`인 발행 상품만. 검색 런타임을 은행 전용으로 강제하지 않음.
- “지금 기능이 packet을 만드는 것”: 실험 브랜치 `product_packet`과 같이, **실행 규칙이 없는 우대**와 **`SOURCE_CLAUSE_GATE` 원문 게이트**만.
- 이미 숫자로 분해된 typed 규칙은 읽기 전용 참고이므로 절 수에 넣지 않음.
- 전 카탈로그 임베딩·LLM 전처리 없음. 키워드·`fact_key`·`source_semantics` 집계 후 사람이 표본을 봄.

### 2.3 사람 검수

키워드 1차는 표본을 보여 주기 위한 것이다. 아래는 다시 묻지 말 것과, 칸으로 쓰면 안 되는 것이다.

**자녀 칸으로 남아야 하는 예**

- 부산은행 아기천사 적금: 가입기간 중 출산. 가족관계증명서 자녀 생년월일. 은행 확인.
- 부산은행 아이사랑 적금: 자녀 연령 구간. 은행 확인.
- 신한 다둥이 상생 적금: 2007년 이후 출생 미성년 자녀 2명/3명. 증빙 승인.
- 하나 아이키움 적금: 미성년 자녀 2명/3명 이상, 서류 제출.
- KB아이사랑적금: 등록 가족 중 만 18세 이하 1명/2명… 동일 문장 티어. **합치지 않고 최댓값.**

**자녀 칸 오탐 (연결을 바꾸어야 함)**

- IBK부모급여우대적금 “부모 or 자녀 명의 청약 신규”: 보유 상품 조건이지 자녀 수 칸이 아니다 → 사전 질문 10번/`UNRESOLVED`.
- 하나 아이키움 마케팅 동의 절에 “다자녀” 광고 문구가 붙어 키워드가 자녀로 읽음 → 마케팅 질문.
- 토스뱅크 태아적금: 가입일 이후 출생 자녀 명의 아이통장 개설·유지. 자녀 수는 필요하지만 토스 아이통장이라는 상품 행동이 남는다 → 자녀 칸만으로 충족 확정 금지, `NEEDS_OFFICIAL`/`UNRESOLVED`.

**임신 칸 표본**

- 신한 다둥이 상생 적금 “결혼, 임신, 난임, 출산 중 해당하는 증빙”. 가입자 본인 임신만이 아니고 서류 승인이다. `PREGNANT_SELF`로 예상 금리를 올리지 말 것.

**같은 원문 티어**

- KB아이사랑적금 미성년 가족 수 1%/2%/… 가 대표 사례다.
- 부산은행 평균잔액 구간, 하나러닝크루 인원, SOL패밀리 구성원 수도 같은 글에서 보상만 갈라진 규칙이다. 자녀가 아니어도 **계산기는 합치지 않고 최댓값**을 쓴다.

**판단 못함으로 둘 것 (새 칸 만들지 않음)**

unread 절의 큰 덩어리는 이런 글이다.

- 만기 납입 잔액 구간, 금리우대쿠폰, 전자명함 신규
- 형제자매 동시 가입, 지자체 지원금, 청년 소득 구간(기관 확인)
- 서민금융진흥원 재무상담 이수, 만기해지 자체 우대
- 제휴채널·이벤트, 기업여신 보유

공통 사용자 입력으로 묶이면 질문이 상품 행동이 되거나, 은행만 아는 확인이 된다. 기존 질문으로 부족한 이유는 한 문장이다.

> 잔액 구간·쿠폰·상담 이수·지자체 지원처럼 상품·기관에 묶인 행동은 전 후보 공통 칸이 될 수 없고, 칸을 늘리면 질문이 다시 상품별로 쪼개진다.

### 2.4 새 칸이 필요한가?

**아니오.** 1차는 있는 질문 + 자녀 칸이면 충분하다.

혼인일 전용 unread 절은 이번 1금융권 packet에서 0건이었다. 임신은 1건이고 서류 승인이다. 칸을 지우지는 않되, 새 칸을 더하지 않는다.

`self_report_eligible`이 11건뿐이라, 답을 받아도 예상(realizable) 금리가 오르는 경우는 드물다. 공통 질문의 본업은 해당 없는 우대를 빼는 것이다.

### 2.5 작업 3·4·5에 넘기는 것

| 후속 | 이 조사가 고정하는 것 |
|---|---|
| 작업 3 연결 | 마케팅/첫거래/카드/급여 원문은 새 질문 금지. 사전 질문 9·10번과 기존 플래너 가족에 붙인다. |
| 작업 4 메모 | 은행 확인 724건은 답해도 `NEEDS_OFFICIAL`. 빈 절·쿠폰·지자체는 `UNRESOLVED`. 자녀 0명은 `RULED_OUT`. |
| 작업 5 티어 | KB아이사랑적금형 동일 문장 1/2/3은 합이 아니라 최댓값. 빈 절 72개는 상품 전체를 버리지 않고 건너뛴다. 43개 상품이 현재 구현이면 통째 실패한다. |

## 성공 기준 대조

계획 문서 작업 1·2 완료 기준:

- 표에 없는 칸을 만들기 전에 있는 질문에 붙일 수 있는지 적었다.
- 1금융권 packet 상품 수·절 수·분류 비율을 적었다.
- 새 칸이 꼭 필요한가: **아니오.**
- 기존 질문으로 부족한 이유: 상품·기관 묶임 행동은 공통 칸이 되면 질문이 다시 쪼개진다.

이 문서는 스위치를 켜라는 뜻이 아니다. 다음 코드 변경은 기능 브랜치의 **같은 원문 티어 최댓값**과 **빈 절 부분 실패**다.
