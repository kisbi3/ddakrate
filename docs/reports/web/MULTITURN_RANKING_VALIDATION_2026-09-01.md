# 다중 턴 추천 순위 검증 보고서 (2026-09-01)

## 목적

실제 Web API에서 사용자의 답변을 여러 턴 누적하고, 각 답변 직후 후보와 순위가 합리적으로 바뀌는지 검증했다. 적금·예금·파킹통장·CMA를 병렬 테스트했으며, 표시 순위는 현재 확정 금리가 아니라 사용자에게 아직 가능한 최고 금리를 기준으로 검증했다. 예상 이자는 현재 적용 가능한 금리로 별도 계산한다.

## 핵심 결론

- 금액과 기간을 입력해도 정렬 기준은 자동으로 이자금순으로 바뀌지 않는다.
- `MAX_REALIZABLE_RATE` 화면 정렬은 사용자별 가능한 최고 금리를 사용하고, 예상 금리와 예상 이자는 현재 적용 가능한 값으로 분리한다.
- 가입 명의, 기관 범위, 장병 여부 등 사전 질문의 답은 다음 질문까지 지연하지 않고 즉시 후보·평가·순위에 반영한다.
- LLM이 부정 답변 `false`를 `DECLARED_FEASIBLE`로 잘못 표기해도 backend가 `DECLINED`로 정규화해 HTTP 400을 피한다.
- 3위 안에 확률형 상품이 들어올 수 있을 때 일반 사전 조건을 모두 확인한 뒤 확률형 포함 여부를 묻고, 제외 시 즉시 순위에서 제거한다.

## KB카드쓰담적금 재현과 수정

### 재현

초기 적금 검색에서 KB카드쓰담적금은 공식 최고금리 12%로 상위권이었다. 사용자가 `월 30만원, 6개월`을 답하면 정렬 기준이 `MAX_REALIZABLE_RATE`에서 `MAX_ESTIMATED_PRE_TAX_INTEREST`로 자동 변경됐고, 현재 적용 가능한 2% 이자로 비교되어 15위까지 밀렸다.

또한 해당 상품의 공시 우대금리는 총 10%p지만 실행 가능한 구조화 규칙은 카드 6%p와 급여 2%p만 있었다. loader가 미구조화된 잔액 구간 2%p까지 제거해 가능한 최고금리를 12%에서 10%로 잘못 축소했다.

### 수정

- 금액·기간 변경은 예상 이자 계산 입력만 갱신하고 기존 정렬 기준을 보존한다.
- 사용자가 명시적으로 `이자금순`을 요청할 때만 `MAX_ESTIMATED_PRE_TAX_INTEREST`로 변경한다.
- 공시 우대 규칙 중 아직 실행 규칙으로 구조화되지 않은 항목이 있으면 공시 가능한 상한을 보존한다.

### 라이브 재검증

세션 `SEARCH-34bffad6ae07cfb0`에서 다음 답변을 누적했다.

1. 정기적으로 돈을 모으고 싶음
2. 월 30만원, 6개월
3. 개인 명의
4. 1990-01-01 출생
5. 청년 정책계좌 미보유
6. 장병내일준비적금 대상 아님
7. 저축은행 포함
8. 신규 거래·급여계좌·카드 조건 원하지 않음
9. 최근 6개월 예금·적금·청약 보유 기관 없음
10. 확률형 상품 제외
11. 마케팅 수신 동의 유지 거절
12. 해당 금융기관 거래 이력 없음

월 30만원·6개월 입력 직후 결과는 다음과 같았다.

| 순위 | 상품 | 가능한 최고금리 | 현재 예상금리 |
|---:|---|---:|---:|
| 1 | 우리 두근두근 행운적금 | 13% | 3% |
| 2 | KB카드쓰담적금 | 12% | 2% |
| 3 | 더쿠폰적금 | 11% | 5% |

확률형 상품 제외 후 우리 두근두근 행운적금이 제거되고 KB카드쓰담적금이 1위가 됐다. 이후 두 차례의 자연어 부정 답변도 HTTP 200으로 처리됐다.

## 병렬 상품군 테스트

### 적금

- 8개 이상의 답변을 누적해 월 납입액, 기간, 명의, 연령, 정책계좌, 장병 자격, 기관 범위, 카드 조건, 보유 이력을 확인했다.
- 기관 범위가 상태에만 저장되고 추천에는 한 턴 늦게 반영되던 문제를 재현하고, 모든 사전 답변 직후 pipeline을 재실행하도록 수정했다.
- 확률형 질문은 일반 조건보다 먼저 나오지 않았고, 실제 Top 3 후보에 확률형 상품이 있을 때만 노출됐다.

### 예금

- 7천만원·2년, 개인 명의, 1988년생, 은행만, 카드·급여이체 불가를 누적했다.
- 개인 명의인데 기업 전용 상품이 남는 현상은 가입 명의 답변의 pipeline 반영 지연과 같은 원인이었다. 즉시 재계산으로 수정했다.

### 파킹통장

- 500만원·6개월 이상, 개인 명의, 기관 범위, 추가 조건 거절을 누적했다.
- 파킹통장만 선택한 세션에서 CMA가 제외됐고 예금자보호 조건도 유지됐다.
- 금융기관 계좌 부정 답변에서 발생한 `DECLARED_FEASIBLE cannot carry a false value` 오류를 backend 정규화로 수정했다.

### CMA

- 300만원·1년, 개인 명의, 연령, 기관 범위, 추가 혜택, 여러 상품 가입대상 여부를 10개 턴 누적했다.
- 실적배당형 CMA는 공시금리 비교 Top 5에 섞이지 않았고, 명시적으로 미해당 처리한 상품은 제거됐다.
- 개인 명의 답변 직후 법인 CMA가 잠시 남는 현상과 자연어 부정 답변 400 오류는 위 공통 수정으로 해결했다.

## 후속 관찰 사항

- 사전 질문은 자연어 해석이 필요한 복합 입력이므로 `/messages`가 정식 제출 경로다. `/answers`로 사전 질문을 제출하면 이제 AssertionError 대신 명시적 400 오류를 반환한다.
- `가입 후 상품 안내·마케팅 수신 동의를 유지할 수 있나요?` 같은 상품 원문 기반 질문은 데이터 문구 개선 대상으로 별도 정리할 필요가 있다.
- 카드·급여 조건을 원하지 않는다는 답은 현재 선호와 실현금리에 반영되지만 상품 자체의 하드 제외 여부는 별도 정책 결정이 필요하다.
